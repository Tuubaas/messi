# Patterns

Every right/wrong way of doing something we have identified, and what enforces it (decision 0007).
Add new entries with the `codify-pattern` skill. Prefer **lint** over **review**: a rule catches every case, a reviewer only some.

| ID   | Pattern                                                                                                                                                                                                       | Why                                                                                                                                           | Enforced by                                                 | Origin                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | --------------------- |
| P001 | Every `createServerFn` uses `requireEditor` middleware or has a `// public-server-fn: <reason>` comment                                                                                                       | Server functions are public HTTP endpoints; route guards are only UX                                                                          | lint `messi/server-fn-guard`                                | 0004                  |
| P002 | POST server functions validate input with `.validator(Schema.toStandardSchemaV1(...))`                                                                                                                        | Inputs come from the network                                                                                                                  | lint `messi/server-fn-post-validator`                       | 0002                  |
| P003 | No `process.env` in app code; Worker settings are decoded with Schema in each app's `src/server/runtime.server.ts`                                                                                            | On Workers env is per-request (module-level reads are `undefined`); one validated entry point                                                 | lint `node/no-process-env`                                  | 0003                  |
| P004 | No `any`                                                                                                                                                                                                      | Types are inferred end to end (TanStack + Effect)                                                                                             | lint `typescript/no-explicit-any`                           | 0002                  |
| P005 | Import Vite+ tooling from `vite-plus/*`, not `vite`/`vitest`/`oxlint` directly                                                                                                                                | One pinned toolchain                                                                                                                          | lint `vite-plus/prefer-vite-plus-imports`                   | 0002                  |
| P006 | Server-only modules that read Worker env end in `.server.ts`                                                                                                                                                  | TanStack import protection fails the build if client code imports them                                                                        | review                                                      | 0003                  |
| P007 | Homepage (and any `headers: noJavaScript` route) adds no client-only behaviour                                                                                                                                | Its JavaScript is stripped; such code silently never runs                                                                                     | review                                                      | 0005                  |
| P008 | No new visual styling on the homepage: colors, fonts, type scales, spacing systems, imagery, animation. Tubas games and the finance app style only with their own tokens (`apps/<app>/src/styles.css`)        | The homepage design is the owner's and still pending; the games and finance designs are decided in 0010 and 0012                              | review                                                      | 0006                  |
| P009 | Markdown components are added to `apps/home/src/content/directives/index.ts` only with an owner decision; attributes are an Effect Schema with `onExcessProperty: "error"`                                    | The registry is the public surface of what content can do                                                                                     | review (+ `defineDirective` types)                          | 0004                  |
| P010 | Effect code follows `node_modules/effect/AGENTS.md`: `Effect.fn`/`fnUntraced`, `Context.Service` + `Layer`, `Schema.TaggedError`, `Predicate` helpers instead of hand-written type guards                     | Consistent, testable server code                                                                                                              | review                                                      | 0002                  |
| P011 | Services are tested by providing fake layers (e.g. `HttpClient.make`, `Jwks.layerLocal`), never by hitting real APIs                                                                                          | Fast, deterministic tests                                                                                                                     | review                                                      | 0002                  |
| P012 | Content-affecting validation runs the same `renderMarkdown` the build runs                                                                                                                                    | What the editor accepts must always build                                                                                                     | review                                                      | 0004                  |
| P013 | Client code in `apps/games` imports only types from `#/game/schema` and `#/buzzer/messages`; what the browser needs at run time lives in `#/game/board`, `#/game/game` and `#/buzzer/room`                    | Keeps Effect Schema out of the play view's JavaScript                                                                                         | review                                                      | 0010                  |
| P014 | A server function that anyone may call returns only what a visitor may see: published boards, and never a draft's existence                                                                                   | Drafts are secret until game night                                                                                                            | review                                                      | 0010                  |
| P015 | Buzzer rules (who may buzz, who was first, how long to wait) live in the pure `apps/games/src/buzzer/room.ts` with tests; `BuzzerRoom` only wires sockets, storage and the clock                              | Fairness has to be testable to the millisecond, which a Durable Object is not                                                                 | review                                                      | 0011                  |
| P016 | A buzz is ordered by its press time in room time, bounded by the sender's latency budget; never by arrival order alone, and never by an unbounded client timestamp                                            | The owner's fairness requirement, and its protection against tampering                                                                        | review (+ `room.test.ts`)                                   | 0011                  |
| P017 | A schema change in `apps/finance` is a new numbered step in `src/server/migrations.ts`, made only of statements that are safe to repeat (`IF NOT EXISTS`, `INSERT OR IGNORE`); a shipped step is never edited | D1 has no transactions: a step can stop halfway and run again on the next start                                                               | test (`Ledger.test.ts` runs every statement twice) + review | 0012                  |
| P018 | Many values go to D1 as one JSON parameter read with `json_each`, never one bound parameter per value; a statement that compares transactions with rules is scoped (one import, one pattern's matches)        | D1 free plan: 100 bound parameters per statement, 50 statements per request, and every row read is billed                                     | review                                                      | 0012                  |
| P019 | Nothing about real money in the repo: finance tests and fixtures use made-up transactions, and server function errors and logs never quote stored data                                                        | The repo is public; a database error can contain what was being stored                                                                        | review                                                      | 0012                  |
| P020 | A box that scrolls sideways (`overflow-x-auto`) and contains visually hidden (`sr-only`) content is also `relative`                                                                                           | Hidden labels are absolutely positioned; without a positioned ancestor they escape the box and make the whole page scroll sideways on a phone | review                                                      | 0012                  |
| P021 | Actions that appear on hover also appear on keyboard focus and on touch screens (`group-focus-within:`, `pointer-coarse:`)                                                                                    | Nothing hovers on a phone                                                                                                                     | review                                                      | 0012                  |
| P022 | State that must follow other state (the page number after a filter changes) is derived or reset while rendering; no effect depends on an object a hook builds anew each render (`useTable(...)`, a mutation)  | Such an effect runs after every render and undoes what the person just did: "Next page" snapped back to page 1                                | review                                                      | 0012 (review finding) |
| P023 | Every path an app's build reads is listed for it in `.github/deploy.json`; an app that starts building from a new place adds it in the same change                                                            | A change outside the list never deploys, and nothing fails to say so                                                                          | review                                                      | 0009                  |
