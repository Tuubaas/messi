# 0009: Monorepo, homepage in apps/home

- Decided by: owner (structure); agent (tooling and layout defaults below)
- Date: 2026-11-17

## Decision

- **The repo is a monorepo.** The homepage app lives in `apps/home`.
- **A push to `main` deploys only the apps it affects** (owner, 2026-11-17). Before, every push deployed every app.

## Agent defaults

The owner can overrule any of these.

| Default                                                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| No extra monorepo tool (no Turborepo or Nx): pnpm workspaces plus Vite+ (`vp run -r`, `--filter`, task caching, root lint/fmt)                                                                                                                                                                                         | Vite+ is already the toolchain (0002) and covers workspace tasks; no new dependency                                                                                                                    |
| Layout: `apps/*` deployable apps, `packages/*` shared libraries, `tools/*` repo tooling                                                                                                                                                                                                                                | The layout `vp create vite:monorepo` generates                                                                                                                                                         |
| Root `vite.config.ts` owns lint, format, test projects and task caching; app configs only build their app                                                                                                                                                                                                              | Vite+ applies root lint/fmt everywhere and ignores package-level blocks in `vp check`                                                                                                                  |
| Package names `@messi/home`, `@messi/lint`; custom lint rules are the `tools/lint` package                                                                                                                                                                                                                             | Lint rules are repo-wide, and get their own tests and dependencies                                                                                                                                     |
| Code shared by apps is a source-only package in `packages/` (first: `@messi/access`, the Cloudflare Access check)                                                                                                                                                                                                      | No build step; each app's bundler compiles it                                                                                                                                                          |
| TanStack Intent runs from the root                                                                                                                                                                                                                                                                                     | It finds skills in every workspace package, so `pnpm exec intent load ...` works anywhere                                                                                                              |
| One deploy workflow for every app. `.github/deploy.json` lists the apps and the paths each is built from: its own folder, plus the paths shared by all (`packages/`, the root install files, the workflow and that file). A first job compares the push with those paths and starts a deploy job for each affected app | Adding an app or a path is a line of config, not a workflow. It costs one short job in front of every deploy. A path too many only costs a deploy; a missing one skips a deploy without failing (P023) |
| Each app's deploys are their own concurrency group, and a deploy job builds the newest commit on `main`, not the one that started it                                                                                                                                                                                   | A content save can't cancel another app's deploy in progress, and of two pushes close together the newest still ends up live                                                                           |
| Running the workflow by hand deploys every app                                                                                                                                                                                                                                                                         | The way to redeploy without a push                                                                                                                                                                     |

## Consequences

- Owner content moves to `apps/home/content/home.md`. The editor commits there, and the CI content guard watches `apps/*/content/`.
- A new app goes in `apps/<name>` and gets an entry in `.github/deploy.json`. Adding one is a new page or product, so it is the owner's decision.
- A content save deploys only the homepage.
- A failed deploy is no longer retried by the next unrelated push. Re-run the failed job, or run the workflow by hand.
