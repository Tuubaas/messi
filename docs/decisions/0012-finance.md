# 0012: Finance, a private personal finance app in apps/finance

- Decided by: owner (the app and what it must do, see Decision); agent (everything else below)
- Date: 2026-11-17

## Decision

- **A third app, a personal finance app, lives in `apps/finance`** (`@messi/finance`), deployed as its own Worker.
- **It is behind auth.** Nothing in it is public.
- The owner **uploads monthly transactions** from credit cards and debit cards, and they are **categorised into a set of categories**.
- Some cards are shared with the owner's partner and some are not, and the owner defines which. **On a shared card only some transactions are shared: each one is shared, the owner's, or the partner's.**
- The owner can **edit a transaction's category**.
- The owner can **customise views** of the finances: graphs and tables, with a changeable time interval.
- **The app has its own functional design**: a restrained, neutral dashboard look. This is for `apps/finance` only; decision 0006 still holds for the homepage.

The owner asked the agent to make reasonable decisions on what was left open. So every row below is an agent default, open to being overruled.

## Agent defaults

### Product and behaviour

| Default                                                                                                                                                                                                                                                                                       | Why                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Only the owner signs in. The partner appears as an owner of transactions, not as a user                                                                                                                                                                                                       | The request speaks of "my" transactions and finances                                                                                                  |
| An **account** is one card or bank account: name, bank, kind (credit card or bank account), and whether it is **shared**                                                                                                                                                                      | "Define which cards/banks we share transactions on"                                                                                                   |
| Every transaction has an **owner**: Mine, Shared or Partner. On a shared account a transaction starts as Shared and can be changed, one at a time or for a whole shop with a rule. On an account that is not shared everything is Mine                                                        | The owner's answer: only some transactions on the shared card are shared                                                                              |
| A view chooses whose transactions count, and can count shared ones at **my share** (a setting, 50% by default) instead of in full                                                                                                                                                             | "My spending" usually means my own plus my half of what we share                                                                                      |
| Upload is **CSV**, one file per account. The file is read in the browser; only the parsed transactions are sent. No Excel or PDF, no bank connection                                                                                                                                          | Every bank exports CSV; it needs no dependency on a bank or a paid service. Excel can be added later                                                  |
| The file's format is **guessed and shown** (delimiter, header, date order, decimal comma, one amount column or separate in/out columns, purchases as positive numbers), can be corrected, and is **remembered per account**                                                                   | Every bank's export is different; next month's upload should be two clicks                                                                            |
| **Uploading the same lines again never duplicates.** A line is the same when account, date, amount, description and its position among identical lines of the file match. Each upload is listed and can be undone                                                                             | Monthly exports overlap, and a file gets uploaded twice by mistake                                                                                    |
| Categorisation is by **rules that learn from the owner's edits**: "description contains X → category (and/or owner)". The longest matching text wins. Changing a transaction offers "apply to all like this", which makes the rule and applies it. What is set by hand is never changed again | Free, private, predictable, and after a month or two almost everything categorises itself. No AI: it would cost money or send transactions to a model |
| Categories have a kind: expense, income or **transfer**. Transfers (paying the card bill, moving savings) count as neither spending nor income. An uncategorised transaction counts by its sign                                                                                               | Otherwise paying the card bill would count the same spending twice                                                                                    |
| Fifteen starter categories and five starter views are created with the database. Both are fully editable                                                                                                                                                                                      | The first import should show something useful                                                                                                         |
| A **view** is saved with: form (bars over time, lines, ranking, table), measure (spending, income, net), split (category, account, owner, none), period (presets or custom dates), column width (day to year), whose money, and optional account and category subsets                         | "Customise different views … graphs, tables, time interval"                                                                                           |
| The overview shows every view, reorderable, with one optional period and column width for all of them at once. Every chart can also be read as a table                                                                                                                                        | One filter row for the page, never one per chart; the table is the accessible twin of each chart                                                      |
| "Last 3 months" means the current month and the two before it                                                                                                                                                                                                                                 | Whole months compare; a rolling 90 days would cut the first one                                                                                       |
| One currency for everything, **SEK** by default, changeable in Settings. Amounts are whole minor units (öre)                                                                                                                                                                                  | A guess from the owner's locale. No floating-point money                                                                                              |
| Routes: `/` overview, `/views/new` and `/views/$viewId` editor, `/transactions`, `/import`, `/settings`                                                                                                                                                                                       | The smallest set that covers the request                                                                                                              |
| Transactions also have a free-text note and can be deleted; search, filters (period, account, category, owner) and bulk edits on the transactions page                                                                                                                                        | Needed to put a month right quickly                                                                                                                   |
| UI copy is the agent's placeholder wording, in English                                                                                                                                                                                                                                        | The owner can reword any of it                                                                                                                        |
| Left out: budgets, recurring-payment detection, several currencies, sharing by other ratios per transaction, a sign-in for the partner, Excel/PDF import, bank connections, AI categorisation, export                                                                                         | Kept the first version to what was asked; each is an owner decision to add                                                                            |

### Design

| Default                                                                                                                                                                | Why                                                                                        |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Neutral surfaces, the system font, one blue accent, hairline borders. Light and dark follow the device                                                                 | "Restrained, neutral dashboard look"; no font dependency                                   |
| **Colour is reserved for data.** Charts use eight hues in a fixed order, checked for colour-blind separation in both modes; a ninth series folds into a grey "Other"   | So that series can be told apart by everyone, and adding a category never invents a colour |
| A category's colour follows its place in the category list, not its rank in the chart. Owners always have the same three colours                                       | A month where groceries overtake rent must not repaint either                              |
| Charts: thin bars with a 2px gap between segments, 2px lines with the end marked and named, hairline grid, a tooltip that lists every series, a legend for two or more | Quiet marks; identity never rests on colour alone                                          |
| A ranking is one bar per group in one colour; net per period is drawn by direction (in/out)                                                                            | Length already says "bigger"; a colour per bar would add nothing                           |
| Charts are drawn with **Recharts**                                                                                                                                     | TanStack has no maintained chart library; Recharts is the common React one                 |
| Tokens live in `apps/finance/src/styles.css`                                                                                                                           | One place to change the look                                                               |

### Architecture

| Default                                                                                                                                                                                                                             | Why                                                                                                                                                                                        |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Everything is stored in Cloudflare D1** (free plan), database `messi-finance`. No financial data is ever in this repository, in test fixtures, or in logs                                                                         | The repo is public (0003). D1 is the database 0010 already introduced                                                                                                                      |
| The **whole site is behind Cloudflare Access**, and every server function also checks the Access token and `EDITOR_EMAIL` (`EditorAuth` from `packages/access`). Without its Access settings the app is locked: it **fails closed** | Unlike the games app there is nothing public to keep running                                                                                                                               |
| The Worker sends only the page shell (`defaultSsr: false`); pages draw in the browser from data fetched through server functions                                                                                                    | Rendering tables and charts of a year of transactions on the server would not fit the Workers free plan's 10 ms of CPU per request                                                         |
| **The browser holds the transactions and does the arithmetic.** They are fetched one calendar year per request and cached; views, filters and search are computed locally                                                           | Changing a view redraws at once, with no request. A year is a few thousand rows                                                                                                            |
| The database builds the JSON of a year's transactions itself and the Worker passes the text on                                                                                                                                      | Turning thousands of rows into objects and back would cost the Worker its CPU budget                                                                                                       |
| An upload is sent in parts of 250 lines; all lines of a part go to D1 as one JSON parameter (`json_each`). Rules are applied by one `UPDATE` per field, always scoped to an import or to one pattern's matches                      | D1 free plan: 100 bound parameters per statement, 50 statements per request, and every row read counts toward 5 million a day                                                              |
| Data access is `effect/sql` with `@effect/sql-d1`; tests run the same SQL and migrations on SQLite in memory (`@effect/sql-sqlite-node`, Node's built-in SQLite)                                                                    | "Server logic is Effect" (0002). The games app's hand-written SQL interface (0010) was enough for one table; this app has seven                                                            |
| The schema is **numbered migration steps**, run when the Worker starts and needed (`src/server/migrations.ts`). Every statement must be safe to repeat                                                                              | 0010 said to revisit migrations when a schema first changes; with seven tables that will be soon. D1 has no transactions, so a step can stop halfway; Effect's own migrator requires them  |
| No foreign keys; deletes remove dependent rows first, statement by statement                                                                                                                                                        | Without transactions, explicit child-first deletes behave the same on D1 and in tests                                                                                                      |
| Server function failures reach the browser as a sentence for the owner, never as the underlying error                                                                                                                               | A database error can quote what was being stored                                                                                                                                           |
| `wrangler.jsonc` has no `database_id`: `wrangler deploy` creates the database on the first deploy                                                                                                                                   | Same as 0010; no manual resource setup                                                                                                                                                     |
| New dependencies: `@tanstack/react-query`, `@tanstack/react-table`, `recharts`, `papaparse`, `@effect/sql-d1`, `@effect/sql-sqlite-node` (tests). Query and Recharts are pinned one release back: their newest were hours old       | Query caches server data, Table does sorting, paging and selection, PapaParse reads CSV (0002: use TanStack features). The pins keep pnpm's minimum-release-age check without an exception |
| Worker name `messi-finance`; dev server on port 3002 (`vp run dev:finance`), with a local database, no sign-in, and no sample data; deployed when a push to `main` affects it (0009) next to the other apps                         |                                                                                                                                                                                            |

## Consequences

- One-time setup for the owner is in [docs/setup.md](../setup.md#finance): three secrets and one Access application covering the whole hostname. Until then the deployed app is locked.
- Cost stays free. D1's free plan allows 5 million rows read and 100,000 written per day; opening the app reads the years on screen (a few thousand rows each), and an upload writes its lines once.
- The data sits in the owner's Cloudflare account. Anyone with access to that account, or to `EDITOR_EMAIL`'s sign-in, can read it.
- An upload that is interrupted leaves the lines sent so far; it is listed under "Earlier imports" and can be undone or simply uploaded again.
- When the Access session expires while the app is open, requests fail until the page is reloaded and the owner signs in again.
- Likely next questions for the owner: Excel import, budgets, recurring payments, a sign-in for the partner, other split ratios, AI suggestions for categories, a custom domain.
